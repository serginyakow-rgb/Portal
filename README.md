# Портал нотариальной конторы

Внутренний портал конторы: FastAPI + SQLAlchemy 2.0 (async) + Jinja2 + SQLite.
Вход в портал выполняется по **имени сотрудника на русском языке и паролю**.

## Стек

- FastAPI 0.115, Uvicorn
- SQLAlchemy 2.0 (async) + aiosqlite
- Jinja2 (шаблоны), passlib/bcrypt (пароли), python-jose (JWT HS256)

## Структура

```text
app/
  core/       config.py, database.py, security.py, templating.py
  db/         base.py (единый DeclarativeBase)
  modules/    auth/ (models, schemas, service, dependencies, routes)
  templates/  base.html, auth/, dashboard/
  static/     css/styles.css, js/app.js
scripts/      create_admin.py
desktop/      launcher.py (трей), portal.spec, portal.iss, build.py — установщик
clinerules/   01-carcass.md — правила проекта
```

Подробная карта проекта — [`PROJECT_MAP.md`](PROJECT_MAP.md): схема слоёв,
маршруты, модели данных, связки шаблонов и JavaScript, сценарии работы.

## Быстрый старт

```powershell
python -m venv venv
venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env      # и подставить свой SECRET_KEY
python scripts/create_admin.py
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Портал: <http://127.0.0.1:8000/auth/login>

## Запуск двойным щелчком (без VS Code)

`start.bat` в корне проекта поднимает портал из Проводника — VS Code не нужен:

```bat
start.bat            :: порт 8000, доступ с других ПК локальной сети
start.bat 8010       :: другой порт
start.bat local      :: доступ только с этого ПК
start.bat admin      :: создать администратора портала
```

Скрипт сам переходит в свою папку, создаёт `venv` и ставит зависимости при первом
запуске, копирует `.env` из `.env.example`, при отсутствии базы предлагает создать
администратора, проверяет занятость порта и открывает браузер только когда сервер
уже слушает порт. Остановка — `Ctrl+C` в окне консоли.
`PORTAL_NO_BROWSER=1` отключает автозапуск браузера. При первом запуске Windows
может запросить для Python доступ в брандмауэре — без него портал не откроется
с других компьютеров конторы.

## Установщик для Windows (`Portal-Setup-1.1.0.exe`)

Готовая сборка не требует Python и VS Code на компьютере конторы: приложение
упаковано вместе с интерпретатором и библиотеками, а установщик ставит его
в профиль пользователя — права администратора не нужны.

**Как это работает после установки.** Установщик кладёт программу в
`%LOCALAPPDATA%\Programs\NotaryPortal`, создаёт ярлыки в меню «Пуск» (и по
желанию на рабочем столе), включает автозапуск при входе в Windows и сразу
запускает портал свёрнутым в трей: браузер не открывается, значок приложения
появляется рядом с часами. Учётная запись нотариуса уже есть — **«Админ»,
пароль «111111»**: её создаёт первый запуск, вход по имени без учёта регистра
(`админ`), пароль меняется в профиле.

Данные лежат рядом с `Portal.exe` и переживают переустановку, удаление
программы и обновление версии:

| Что | Где |
| --- | --- |
| База портала | `portal.db` (рядом с `Portal.exe`) |
| Резервные копии | `backups\` |
| Настройки и `SECRET_KEY` | `.env` (создаётся при первом запуске со случайным ключом) |
| Журнал запуска | `portal-desktop.log` |
| Ключ и токен Google Календаря | `config\google_calendar\` |

**Меню значка в трее — четыре пункта:**

| Пункт | Что делает |
| --- | --- |
| «Открыть в браузере» | страница входа на этом компьютере (то же — двойной щелчок по значку) |
| «Адрес подключения для локальных ПК: `http://192.168.0.5:8000`» | готовый адрес для рабочих мест конторы: щелчок копирует его в буфер обмена и показывает уведомление; если сети нет, пункт неактивен и сообщает «сеть не найдена» |
| «Открыть папку с данными» | папка программы: `portal.db`, `backups\`, `.env`, `config\google_calendar\`, журнал |
| «Выход» | останавливает сервер и убирает значок из трея |

- Портал слушает `0.0.0.0`, поэтому доступен с других компьютеров конторы:
  адрес для набора на рабочих местах показывает второй пункт меню трея и
  подсказка значка. При первом запуске Windows спрашивает разрешение для
  программы в брандмауэре — нужно ответить «Разрешить доступ». Если окно не
  появилось, а другие компьютеры портал не открывают, правило добавляют один
  раз от имени администратора:
  `netsh advfirewall firewall add rule name="Портал нотариальной конторы" dir=in action=allow protocol=TCP localport=8000`.
- Повторный запуск ярлыка не поднимает второй сервер: приложение находит
  работающий портал и просто открывает страницу входа.
- Если порт 8000 занят, портал берёт следующий свободный (8001, 8002, …);
  основной порт задаётся строкой `PORTAL_PORT` в `.env`.
- Учётная запись нотариуса «Админ» с паролем `111111` создаётся при первом
  запуске установленного портала (только в пустую базу: данные работающего
  портала не затрагиваются). Пароль лучше сразу сменить в профиле.
- Новых нотариусов добавляют ярлыком «Портал нотариальной конторы — создать
  администратора» в меню «Пуск»: откроется консоль, где скрипт спросит имя и
  пароль (в меню трея этого пункта нет — там ровно четыре пункта).
- Остановка портала — пункт «Выход» в меню значка.
- При удалении программы база, настройки и резервные копии по умолчанию
  остаются на месте; удалить их можно, отметив соответствующий пункт
  в установщике.

### Сборка установщика

```powershell
venv\Scripts\python.exe desktop\build.py                 # Portal-Setup-1.1.0.exe
venv\Scripts\python.exe desktop\build.py --version 1.2.0 # новая версия
venv\Scripts\python.exe desktop\build.py --install-inno   # доставить Inno Setup
venv\Scripts\python.exe desktop\build.py --skip-installer # только папка dist\Portal
```

Скрипт ставит пакеты из `desktop\requirements-desktop.txt` (PyInstaller,
pystray, Pillow), собирает `desktop\portal.ico` из `logo.jpg`, упаковывает
`desktop\launcher.py` в `desktop\dist\Portal\Portal.exe`, кладёт рядом шаблоны,
статику и `scripts\create_admin.py` и собирает установщик Inno Setup в
`desktop\output\Portal-Setup-<версия>.exe`.

Файлы настольной сборки:

```text
desktop/
  launcher.py               значок в трее, запуск uvicorn, браузер, меню
  make_icon.py              logo.jpg -> portal.ico
  portal.spec               конфигурация PyInstaller
  portal.iss                сценарий установщика Inno Setup
  build.py                  сборка одной командой
  requirements-desktop.txt  пакеты настольной сборки
```

Для сборки нужен интерпретатор из `venv`, Inno Setup 6 (ключ `--install-inno`
скачивает его сам) и доступ в интернет.

## Вход и роли

- Логин — имя сотрудника: только русские буквы, пробел и дефис (например, `Иванов Иван Иванович`).
- Пароль проверяется по bcrypt-хешу; JWT лежит в httpOnly-cookie `portal_token`.
- В токене хранится только `id` пользователя, поэтому смена имени и пароля не разрывает активную сессию.
- Рядом с хешем пароль хранится в открытом виде (`password_plain`): администратор видит его в разделе «Пользователи» и может выдать сотруднику заново.
- Неавторизованный запрос (401) ведёт на `/auth/login`, запрос без прав (403) — на `/dashboard?denied=1`.

| Раздел | Маршрут | Доступ |
| --- | --- | --- |
| Вход | `GET/POST /auth/login` | все |
| Выход | `POST /auth/logout` | авторизованные |
| Панель | `GET /dashboard` | авторизованные |
| Пользователи: список, добавление, форма правки | `GET /settings/users` (`?edit=<id>` — форма правки) | только `admin` |
| Добавление сотрудника | `POST /settings/users` | только `admin` |
| Изменение имени и пароля сотрудника | `POST /settings/users/{id}/update` | только `admin` |
| Удаление сотрудника | `POST /settings/users/{id}/delete` | только `admin` (кроме себя) |
| Свой профиль | `GET /auth/profile` | авторизованные |
| Смена собственного пароля | `POST /auth/profile/password` | авторизованные |

## Google Календарь

Раздел **Настройки → Связь с Google Календарём** (`/settings/google-calendar`,
только администратор): загрузка ключа OAuth-клиента, вход в Google на компьютере
с порталом, статус связи и проверка тестовым событием.

Полная инструкция — от настроек Google Cloud (Calendar API, экран согласия,
Test users, scope `.../auth/calendar`, Desktop-клиент) до проверки события в
портале: [`SetupCal.md`](SetupCal.md). Там же разбор ошибок `403 access_denied`,
`redirect_uri_mismatch` и ограничение режима Testing (токен на 7 дней).

## Резервное копирование

Раздел **Настройки → Резервное копирование** (`/settings/backup`, только
администратор): один файл `portal-backup-YYYYMMDD-HHMMSS.json` со всеми данными
портала — сотрудники, региональные тарифы, шаблоны карточек («Задачи»), база
заготовок, задачи (включая корзину), контакты и состояние Google Календаря.

- **Создать копию** — кнопка «Создать и сохранить»: файл появляется в папке
  `backups/` на компьютере портала (путь задаётся переменной `BACKUP_DIR`).
- **Открыть папку** — кнопка рядом с «Создать и сохранить»: в проводнике
  компьютера портала открывается папка с файлами копий (`backups/`).
- **Скачать** — кнопка у файла в таблице: браузер спросит, куда сохранить.
- **Восстановить** — из файла в папке или с компьютера. Режим один: «заменить
  всё». Перед заменой портал сам сохраняет копию текущего состояния в
  `backups/`, поэтому откат возможен даже после ошибки в самой копии.
- **Секреты по умолчанию не входят**: открытые пароли сотрудников и ключ/токен
  Google попадают в файл только по чекбоксам. Из копии без паролей сотрудники
  восстанавливаются со своими прежними паролями, а новые — неактивными: пароль
  им выдаёт нотариус в разделе «Пользователи».
- Папка `backups/` исключена из git: в файлах данные сотрудников и, возможно,
  секреты Google.

Новый раздел портала подключается к копии одной записью
`register(BackupSection(...))` в `app/modules/<модуль>/backup.py` — см.
[`PROJECT_MAP.md`](PROJECT_MAP.md), §4.6 и §9.

## Переменные окружения (.env)

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `SECRET_KEY` | подпись JWT | `dev-secret-change-me` |
| `DATABASE_URL` | строка подключения | `sqlite+aiosqlite:///./portal.db` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | время жизни токена | `480` |

## Примечания

- Таблицы создаются автоматически при старте приложения (`Base.metadata.create_all`), миграции Alembic пока не настроены. При изменении схемы существующей базы колонку добавляют вручную, например:
  `ALTER TABLE users ADD COLUMN password_plain VARCHAR(128);`
- Пароли, заданные до появления просмотра, в открытом виде не сохранены (в списке видно «—»): администратору нужно выдать такой сотрудник новый пароль, после чего он появится в колонке «Пароль».
- `styles.css` в корне — утверждённый дизайн-код; рабочие шаблоны используют только его классы (файл-копия — `app/static/css/styles.css`).
