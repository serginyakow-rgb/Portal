# Состояние и хроника работ

## Что уже работает

- **Каркас**: FastAPI + серверный рендеринг, единый `render()` с общим
  контекстом, статика без кеша, `Base.metadata.create_all` при старте,
  логи в `uvicorn.log` / `uvicorn.err`.
- **Вход и пользователи**: вход по ФИО и паролю (bcrypt), JWT в httpOnly-cookie,
  401 → `/auth/login`; админ-раздел «Пользователи» со списком, добавлением,
  правкой имени/пароля, удалением (кроме себя); «Мой профиль» со сменой пароля.
- **База заготовок** (`templates_db`): разделы (создание, правка, удаление
  с защитой от непустого раздела), заготовки (создание, просмотр, копирование,
  правка, удаление), теги, поиск по разделу/тегу/тексту; клиентский скрипт
  `templates_db.js` (265 строк) с фильтрами и диалогами.
- **Калькуляторы** (4 страницы + список карточек): три клиентских
  (`kuplya-prodazha`, `udostoverenie-dkp`, `udostoverenie-dareniya`) и один
  серверный (`gosposhlina`); общий формат денег в полях — `money-input.js`.
- **Федеральный тариф 0,5 % с границами 300 ₽ / 20 000 ₽** действует в двух
  клиентских калькуляторах: обязательная нотариальная форма ДКП
  (`calculators.js`) и удостоверение договора дарения
  (`udostoverenie-dareniya.js`, где до этого считаются стоимость даримой доли
  и деление вдвое для родственников) — см. `activeContext.md`.
- **Блок показателей** (`.calc__out`) во всех калькуляторах прижат к верхнему
  краю (`justify-content: flex-start`), поэтому подпись первого показателя
  стоит на одной линии с подписью первого поля ввода.

## Незавершённое и известные вопросы

- **Минимум 300 ₽ при пустой цене** — открытый вопрос к пользователю: сейчас
  при пустом (или мусорном) поле стоимости показатель равен 0 ₽ — так и в
  `calculators.js` (ДКП), и в `udostoverenie-dareniya.js` (там 0 при
  стоимости даримой доли 0); альтернатива — показывать 300 ₽ всегда.
- **Ставки нотариальных тарифов** (в `TARIFFS` для госпошлины и в клиентских
  калькуляторах) помечены в коде как «УТОЧНИТЬ У НОТАРИУСА» — сверять
  с практикой конторы перед изменениями.
- **Формула «Итого» в калькуляторе дарения** расходится с правилом раздела:
  сейчас `round(федеральный) + round(региональный)`, а `clinerules`
  (раздел «Числа», правило 12) требует «Итого» по неокруглённым значениям
  (разница до 1 ₽). Правку не делали: пользователь просил оставить остальные
  расчёты прежними.
- **Alembic-миграции не настроены**: схемы создаются автоматически, при
  изменении существующей БД колонки добавляются вручную.
- **Устаревшие примечания README** (структура проекта, раздел «Панель»,
  ручные `ALTER TABLE`) — README отстаёт от кода.
- **`app/static/_probe.html`** — диагностический файл (измерения вёрстки),
  отслеживается git; роутов нет, кандидат на удаление.
- **Разделы из исходного каркаса** («Лица», «Карточки», «Канбан», «Календарь»)
  в меню и коде отсутствуют: не начинать их без отдельной задачи.

## Как продолжать работу

1. Прочитать `clinerules/01-carcass.md` и `clinerules/02-calculators.md`.
2. Свериться с `memory-bank/activeContext.md` (текущая задача) и
   `memory-bank/systemPatterns.md` (паттерны кода).
3. Перед правкой расчётов проверить формулу с пользователем, после — прогнать
   проверки и сохранить CRLF/UTF-8:

```powershell
node --check app\static\js\calculators.js                    # синтаксис
node "$env:TEMP\test_kuplya_prodazha.js" app\static\js\calculators.js                    # 122 проверки
node "$env:TEMP\test_udostoverenie_dareniya.js" app\static\js\udostoverenie-dareniya.js  # 74 проверки
python "$env:TEMP\http_check_kuplya.py"                      # 29 проверок (нужен запущенный сервер)
```
