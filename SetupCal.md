# SetupCal — подключение портала к Google Календарю

Пошаговая инструкция: от настроек в Google Календаре и Google Cloud до проверки
связи внутри портала. Расчётное время первого подключения — 15–20 минут,
повторное (после истечения токена) — 1 минута.

Раздел в портале: **Настройки → Связь с Google Календарём**
(`/settings/google-calendar`), доступен только администратору.

---

## 0. Как это устроено (прочитать до начала)

| Что | Как работает |
| --- | --- |
| Один аккаунт Google на портал | События пишутся в **основной календарь** (`primary`) того аккаунта, который подключён |
| Вход — один раз | Вход в Google выполняется на **компьютере, где запущен портал**, и только по адресу `localhost` / `127.0.0.1` |
| Токен общий | После подключения сохранённый токен используют все сотрудники: статус, проверка и создание событий работают с любого ПК локальной сети |
| Почему только localhost | Google возвращает код подтверждения только на loopback-адреса и отклоняет приватные адреса вида `192.168.x.x` (политика secure response handling) |
| Где лежат секреты | `config/google_calendar/credentials.json` (ключ OAuth-клиента), `token.json` (токен), `account.txt` (почта аккаунта). Папка исключена из git |
| Права | Один scope: `https://www.googleapis.com/auth/calendar` — просмотр и создание событий |
| Где используется | Сейчас — раздел настроек (подключение и проверка тестовым событием); сохранённый токен доступен другим модулям портала для записи событий по делам |

Что НЕ нужно: отдельный проект Google на каждого сотрудника, сервер в интернете,
оплата, публикация приложения.

## 1. Подготовка на компьютере с порталом

1. Портал запущен и открывается **на этом же компьютере**:
   `http://localhost:8000/auth/login`.
   Запуск: `start.bat` (или `run.bat`) в папке проекта, остановка — `Ctrl+C` в окне консоли.
2. Библиотеки Google установлены. Проверка в PowerShell из папки проекта:

   ```powershell
   venv\Scripts\python.exe -c "import google_auth_oauthlib.flow, googleapiclient.discovery; print('OK')"
   ```

   Если ошибка — `venv\Scripts\python.exe -m pip install -r requirements.txt`
   и перезапустить портал. В разделе настроек при этом будет сообщение
   «Библиотеки Google не установлены».
3. Вход в портал выполнен **под администратором** (раздел настроек недоступен
   остальным ролям).
4. Под рукой аккаунт Google, в календарь которого будут попадать события
   (личный `@gmail.com` или рабочий в домене Google Workspace).
5. Открыт [Google Cloud Console](https://console.cloud.google.com/) под тем же
   аккаунтом.

> Номер проекта Google понадобится дальше: он берётся из `client_id`
> (часть до дефиса, например `162583412112` в
> `162583412112-plg7q4egq71l4852uupv7q2a9ifd4tvq.apps.googleusercontent.com`).
> Ссылки ниже можно открывать с `?project=ВАШ_НОМЕР`.

## 2. Настройка в Google Cloud (один раз)

Все шаги выполняются в одном проекте. Названия пунктов консоли периодически
меняются: экран согласия теперь называется **Google Auth Platform**
(в коде портала и в старых инструкциях — «OAuth consent screen»).

### 2.1. Проект

1. [console.cloud.google.com](https://console.cloud.google.com/) → вверху
   выбрать проект или **New Project** → название, например
   `notary-portal-calendar` → **Create**.
2. Убедиться, что в шапке выбран именно этот проект — все дальнейшие шаги
   действуют только внутри него.

### 2.2. Включить Google Calendar API

1. **APIs & Services → Library** (или
   [прямая ссылка](https://console.cloud.google.com/apis/library/calendar-json.googleapis.com)).
2. Найти **Google Calendar API** → **Enable**.

Без этого шага вход может пройти, но создание события вернёт ошибку
`Google не принял событие: ... accessNotConfigured`.

### 2.3. Экран согласия: Google Auth Platform

Открыть [Google Auth Platform → Overview](https://console.cloud.google.com/auth/overview).
Если консоль предлагает **Get started** — пройти мастер, он же создаёт три
раздела: Branding, Audience, Data Access.

**Branding (брендинг):**

| Поле | Значение |
| --- | --- |
| App name | `Портал нотариальной конторы` (это имя увидит нотариус на экране Google) |
| User support email | почта администратора |
| Developer contact information | та же почта |

**Audience (аудитория) — самое важное для входа:**

1. **User type**:
   - `External` — для личного аккаунта `@gmail.com`;
   - `Internal` — если аккаунт в домене Google Workspace и портал нужен только
     сотрудникам этого домена (**рекомендуется для конторы**: нет проверки
     Google и нет 7-дневного ограничения токена, см. п. 6).
   - Тип выбирается при первичной настройке; сменить External → Internal у
     существующего приложения нельзя — придётся создать новый проект.
2. **Publishing status** должен быть **Testing**. Если стоит `In production`,
   нажать **Back to testing**: приложение не проходило верификацию Google, и
   вход для сторонних аккаунтов будет отклоняться.
3. **Test users → Add users** → вписать **точный e-mail** аккаунта, под которым
   будете входить (тот же, что выбран в браузере) → **Save**.
   Пока аккаунта нет в списке, Google отвечает `403: access_denied`.
   Ограничение — 100 тестовых пользователей, для конторы достаточно.

**Data Access (доступ к данным):**

1. **Add or remove scopes**.
2. Найти и отметить `https://www.googleapis.com/auth/calendar`
   (группа «Google Calendar API», описание «See, edit, share, and permanently
   delete all the calendars…»). Если в списке не находится — вставить URL scope
   в поле «Manually add scopes» → **Add to table**.
3. **Update / Save**. Больше никаких scope порталу не нужно.

### 2.4. Создать ключ OAuth-клиента

1. [Google Auth Platform → Clients](https://console.cloud.google.com/auth/clients)
   (старый путь: **APIs & Services → Credentials**) → **Create client**
   (в старом интерфейсе — **Create credentials → OAuth client ID**).
2. **Application type** — строго **Desktop app**. Не «Web application»:
   у веб-клиента адрес возврата фиксированный, а портал слушает случайный порт
   на `localhost`, и Google ответит `redirect_uri_mismatch`.
3. Name — например `Portal desktop` → **Create**.
4. **Download JSON** — сохранится файл
   `client_secret_<номер>-<идентификатор>.apps.googleusercontent.com.json`.
   Внутри блок `"installed"` с полями `client_id`, `client_secret`,
   `redirect_uris: ["http://localhost"]` — это правильный файл.

Файл ключа — секрет. Не отправлять его в мессенджерах и почте; передавать
только на компьютер портала (флешка, сетевой ресурс) и сразу загружать в портал.

### 2.5. Дополнительно для Google Workspace

Если аккаунт рабочий (`notary@yourdomain.ru`), администратор домена может
блокировать сторонние приложения:

1. [admin.google.com](https://admin.google.com/) → **Security → Access and data
   control → API controls → App access control**.
2. Настроить доступ: либо «Allow all», либо добавить приложение в доверенные
   (по `client_id`), либо разрешить для конкретного подразделения.
3. Проверить, что пользователю не ограничен доступ к Google Calendar
   (**Apps → Additional Google services**).

Признак этой блокировки — экран Google «Access blocked: … has not completed the
verification process» или сообщение о политике администратора.

## 3. Загрузка ключа в портал

1. На сервере портала открыть `http://localhost:8000/settings/google-calendar`
   (или **Настройки → Связь с Google Календарём**).
2. Блок **«Ключ OAuth-клиента»** → поле **«Файл client_secret_*.json»** →
   выбрать скачанный ключ → **«Загрузить ключ»**.
3. Ожидаемый результат: зелёная строка
   «Ключ OAuth-клиента сохранён. Следующий шаг — подключение к календарю»,
   в шапке блока — «Файл загружен», ниже появляется кнопка **«Удалить ключ»**.

Ключ сохраняется как `config/google_calendar/credentials.json`.

| Сообщение портала | Причина |
| --- | --- |
| Файл ключа не выбран | Форма отправлена без файла |
| Файл ключа слишком большой: ожидается JSON размером до 64 КБ | Выбран не тот файл (например, архив или картинка) |
| Файл не похож на JSON-ключ OAuth-клиента | Файл повреждён или это не JSON |
| В файле нет блока installed или web — это не ключ OAuth-клиента Google | Скачан не тот JSON (например, ключ сервисного аккаунта) |
| В ключе нет client_id / client_secret | Файл обрезан при передаче — скачать заново |
| Не удалось сохранить ключ в config\google_calendar\credentials.json | Нет прав на запись в папку проекта (запуск из защищённой папки, диск только для чтения) |

Загрузка нового ключа **сбрасывает прежний токен**: после замены ключа вход в
Google нужно выполнить заново.

## 4. Подключение (вход в Google)

Выполняется **на компьютере с порталом** — кнопка есть только там.

1. Открыть `http://localhost:8000/settings/google-calendar`
   (адрес `127.0.0.1:8000` равнозначен; открывать по имени компьютера или
   `192.168.x.x` нельзя — кнопка заменится подсказкой с правильным адресом).
2. Блок **«Подключение»** → **«Подключить календарь»**.
3. Откроется окно браузера Google:
   - выбрать аккаунт **из списка Test users**;
   - проверить, что приложение называется «Портал нотариальной конторы»;
   - на экране «Google не подтвердил это приложение» → **Дополнительные
     настройки / Перейти (небезопасно)** — это ожидаемо для режима Testing;
   - **Разрешить** доступ к календарю.
4. Браузер покажет «Готово: доступ к Google Календарю получен. Окно можно
   закрыть.» Страница портала обновится сама (она опрашивает состояние входа).

Пока идёт ожидание, на странице висит строка «Ожидаем подтверждение входа в
Google…», портал ждёт до **5 минут**. Если окно не открылось, ссылка для входа
печатается в окне консоли портала — скопировать её в браузер на этом же
компьютере.

Успешный итог: строка «Google Календарь подключён: <почта>» и кнопки
**«Отключить календарь»**, **«Создать тестовое событие»**.

С другого компьютера локальной сети раздел показывает статус связи и подсказку,
что вход выполняется на сервере портала (`http://localhost:8000/settings/google-calendar`).

## 5. Проверка связи

1. Блок **«Проверка связи»** → **«Создать тестовое событие»**.
2. Появится сообщение «Тестовое событие создано: Проверка связи с Google
   Календарём, <дата> 10:00» и кнопка **«Открыть в Календаре»** (ссылка на
   событие).
3. Событие: завтра в 10:00, длительность 30 минут, в **основном** календаре
   подключённого аккаунта. Открыть его в Google Календаре и убедиться, что
   календарь и почта те самые.

Если событие не создалось, портал покажет текст ошибки Google — см. п. 8.

## 6. Ограничения и сроки

| Ограничение | Что значит на практике |
| --- | --- |
| **Testing + External** → токен живёт 7 дней | Google выдаёт refresh-токен на неделю. Раз в неделю портал покажет «Google отклонил сохранённый токен — подключите календарь заново»: открыть раздел на сервере и нажать «Подключить календарь» (ключ загружен, повторная загрузка не нужна) |
| **Internal** (Workspace) | Токен не истекает по недельному правилу, верификация Google не нужна — лучший вариант для конторы с доменом |
| Лимит тестовых пользователей | 100 аккаунтов |
| Только основной календарь | События пишутся в `primary` подключённого аккаунта; отдельный «календарь конторы» не выбирается |
| Один аккаунт на портал | Ключ и токен одни на всю контору; чтобы сменить аккаунт — «Отключить календарь» и войти другим |
| Часовой пояс | Передаётся смещение местного времени сервера. Если нужен явный пояс IANA, задать переменную `TZ=Europe/Moscow` перед запуском портала |
| Интернет | Нужен и при подключении, и при каждом обращении к календарю: без сети события не создаются |

### 6.1. Как убрать недельное переподключение

1. **Internal (рекомендуется)** — если аккаунт в Google Workspace: новый проект,
   User type `Internal`, тот же ключ Desktop, повторная загрузка ключа и вход.
2. **Верификация Google** — выход из Testing в `In production`. Для scope
   `.../auth/calendar` требуется публикация с проверкой (демонстрация работы,
   политика конфиденциальности на домене, ответ на вопросы Google). Для
   внутреннего портала обычно нецелесообразно.
3. **Сервисный аккаунт** — вход через браузер не нужен совсем: календарь
   расшаривается на e-mail сервисного аккаунта с правом «Вносить изменения».
   Требует доработки портала (реализуется по запросу).

## 7. Обслуживание: смена аккаунта, отключение, перевыпуск ключа

| Задача | Действие |
| --- | --- |
| Временно отключить календарь | **«Отключить календарь»** — удаляется только токен, ключ остаётся; далее «Подключить календарь» |
| Полностью убрать интеграцию | **«Удалить ключ»** — удаляются ключ, токен и сохранённая почта аккаунта |
| Сменить аккаунт Google | «Отключить календарь» → при необходимости выйти из аккаунта в браузере → «Подключить календарь» → выбрать другой аккаунт (он должен быть в Test users) |
| Отозвать доступ со стороны Google | [myaccount.google.com/permissions](https://myaccount.google.com/permissions) → «Портал нотариальной конторы» → **Удалить доступ**. После этого портал попросит подключиться заново |
| Ключ попал в чужие руки | В консоли: Clients → ваш Desktop-клиент → **Delete**; создать новый Desktop-клиент, скачать JSON, загрузить в портал через «Удалить ключ» + «Загрузить ключ», затем подключиться заново. Старый токен при удалении клиента перестаёт действовать |
| Переустановка / перенос портала | Скопировать папку `config/google_calendar` (ключ + токен) — связь сохранится; иначе подключиться заново |
| Резервная копия | Хранить `credentials.json` не обязательно (ключ всегда можно скачать в консоли), `token.json` — секрет, копировать только на защищённый носитель |

## 8. Диагностика: сообщение → причина → решение

Портал показывает текст ошибки в разделе настроек, а при отказе во входе — ещё и
подсказку под ним.

### 8.1. Ошибки на шаге «Подключить календарь»

| Сообщение | Причина | Решение |
| --- | --- | --- |
| `Google отклонил доступ (403 access_denied): аккаунт не входит в список тестовых пользователей…` | Аккаунт не добавлен в Test users, приложение в `In production` без верификации, либо запрет администратора домена | Audience → Publishing status = **Testing**, добавить e-mail в **Test users**; проверить Data Access (scope `.../auth/calendar`); для Workspace — разрешить приложение в admin.google.com |
| `Google отклонил адрес возврата: подключение выполняется только на компьютере с порталом` (`redirect_uri_mismatch`) | Портал открыт не по `localhost`/`127.0.0.1`, либо ключ создан как **Web application** | Открыть `http://localhost:8000/settings/google-calendar` на сервере; ключ должен быть от **Desktop app** |
| `Invalid client` / `unauthorized_client` (в тексте ошибки) | Ключ от другого проекта, клиент удалён, `client_secret` не совпадает | Скачать ключ заново в Clients → Download JSON, загрузить в портал, повторить вход |
| `Сначала загрузите файл ключа OAuth-клиента (client_secret_*.json)` | Кнопка нажата до загрузки ключа | Загрузить ключ (п. 3) |
| `Не установлены библиотеки Google: выполните pip install -r requirements.txt…` | В окружении нет `google-api-python-client` / `google-auth-oauthlib` | Установить зависимости и перезапустить портал |
| `Подключение уже выполняется: завершите вход в открывшемся окне браузера` | Предыдущая попытка ещё ждёт подтверждения | Завершить вход в окне Google или подождать до 5 минут |
| `Время ожидания истекло: вход в Google не подтверждён. Нажмите «Подключить» ещё раз` | Окно закрыли или не завершили вход за 5 минут | Повторить подключение |
| `Не удалось подключиться к Google Календарю: <текст>` | Прочие сетевые ошибки, прокси, антивирус | Читать текст; проверить интернет и доступ к `accounts.google.com` |

**Как определить причину по экрану Google** (важнее текста ошибки в портале):

| Что видно в браузере | Причина |
| --- | --- |
| Сразу «Access blocked / Ошибка 403: access_denied», **без** выбора аккаунта и без экрана «Разрешить» | Аккаунт не в Test users, приложение в `In production` без верификации либо запрет администратора домена |
| Есть выбор аккаунта и экран «Разрешить», но после нажатия отказ | Нажата «Отмена» либо аккаунт заблокирован политикой домена |
| «Access blocked: … has not completed the verification process» | Публикация `In production` без верификации → вернуть Testing или добавить аккаунт в Test users |
| «Admin has blocked …» / «Заблокировано администратором» | Google Workspace: разрешить приложение в admin.google.com (п. 2.5) |
| «Invalid client» / «Ошибка 401: invalid_client» | Ключ в портале не от этого проекта или клиент удалён |
| Открылся не тот аккаунт | В браузере несколько профилей: выйти из лишних аккаунтов или открыть ссылку из консоли портала в приватном окне и войти нужным аккаунтом |

### 8.2. Ошибки в строке статуса

| Сообщение | Причина | Решение |
| --- | --- | --- |
| `Ключ загружен, но подключение к календарю не выполнено` | Токена ещё нет | Нажать «Подключить календарь» на сервере |
| `Google отклонил сохранённый токен — подключите календарь заново` | Истёк 7-дневный refresh-токен (Testing), доступ отозван, ключ перевыпущен | Повторить вход (п. 4); для устранения навсегда — п. 6.1 |
| `Срок действия токена истёк — подключите календарь заново` | В токене нет refresh-токена (вход без `access_type=offline`) | Повторить вход через портал, не вручную |
| `Не удалось проверить сохранённый токен: <текст>` | `token.json` повреждён, нет сети, системное время сильно сбито | Удалить токен кнопкой «Отключить календарь» и войти заново; проверить дату/время и интернет |
| `Библиотеки Google не установлены…` | Зависимости не установлены | `pip install -r requirements.txt`, перезапуск |

### 8.3. Ошибки на шаге «Создать тестовое событие»

| Текст Google | Причина | Решение |
| --- | --- | --- |
| `accessNotConfigured` / `SERVICE_DISABLED` | Google Calendar API не включён в проекте | Library → Google Calendar API → **Enable** (п. 2.2) |
| `insufficientPermissions` / `insufficientScopes` | В токене нет права записи (не тот scope) | Data Access → добавить `.../auth/calendar`, затем «Отключить календарь» и войти заново |
| `notFound` | У аккаунта нет основного календаря / календарь удалён | Войти другим аккаунтом |
| `quotaExceeded` / `rateLimitExceeded` | Превышены лимиты запросов | Подождать, повторить позже |
| `Google не принял событие: <текст>` | Любая ошибка API с текстом | Разбирать по тексту выше |

### 8.4. Полезные проверки вручную

## 10. Безопасность

- `config/google_calendar/` содержит ключ клиента и токен доступа к календарю.
  Папка исключена из git (`.gitignore`), в резервные копии общего доступа не
  попадает.
- Не пересылать `credentials.json`, `token.json` и содержимое `client_secret_*.json`
  по почте и мессенджерам; не публиковать скриншоты с `client_secret`.
- Токен даёт право читать и изменять **весь** календарь аккаунта. Если компьютер
  с порталом выбывает из строя или уходит на ремонт — отозвать доступ:
  [myaccount.google.com/permissions](https://myaccount.google.com/permissions),
  либо в портале «Удалить ключ».
- Доступ к разделу настроек есть только у администратора портала; пароль
  администратора не должен быть общим.
- При смене сотрудника, отвечавшего за интеграцию, не обязательно менять ключ:
  достаточно «Отключить календарь» и подключить его заново под нужным аккаунтом.

## 11. Что делает портал (для разработчика)

| Файл | Роль |
| --- | --- |
| `app/modules/google_calendar/service.py` | Вся работа с Google: валидация и сохранение ключа, фоновый вход через `InstalledAppFlow.run_local_server(host="localhost", port=0)`, хранение и обновление токена, создание событий, тексты ошибок и подсказок (`_connect_error_message`, `_connect_error_hint`), состояние входа (`connect_state`) |
| `app/modules/settings/routes.py` | Маршруты раздела: `GET /settings/google-calendar`, `POST .../credentials`, `POST .../credentials/delete`, `POST .../connect`, `GET .../connect/status`, `POST .../disconnect`, `POST .../test-event` (все — только `admin`) |
| `app/templates/_google_calendar_panel.html` | Панель раздела: ключ, подключение, проверка, подсказки по ошибкам |
| `app/static/js/google-calendar.js` | Опрос `/connect/status`, пока идёт вход в Google; автоперезагрузка после успеха |
| `config/google_calendar/` | `credentials.json`, `token.json`, `account.txt` — секреты, в git не попадают |
| `requirements.txt` | `google-api-python-client`, `google-auth-httplib2`, `google-auth-oauthlib` |

Ключевые константы: `SCOPES` (один scope `.../auth/calendar`),
`MAX_CREDENTIALS_SIZE` = 64 КБ, `CONNECT_TIMEOUT_SECONDS` = 300,
`LOOPBACK_HOSTS` = `localhost`, `127.0.0.1`, `::1`.
